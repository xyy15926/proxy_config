##  根本要求

-   你正在总结知识笔记，知识笔记应该是从文章中提取知识、重组为新的知识库体系，而不是简单的总结文章
    -   内容上，需要保持克制、精确、要点突出的同时保证覆盖全部重要的细节
        -   内容要克制，不需要口语化、情绪化的表达，要尽量的客观、减少不必要的修饰词
        -   内容要精确，要准确的描述概念、准确的划分层级、准确的归因
        -   要突出要点，将重点概念分层次、分项拆解，明确提炼出重点、核心知识点
    -   结构上，知识笔记需要分文档、分章节、分要点分别整理、总结
    -   但同时，关系上，知识笔记之间要相互关联，并构建成为知识体系、知识网络
        -   已有的知识点要检查是否与历史记录矛盾、重复，辨析之后补充、更新或维持不变
        -   新知识点要作为当次总结的重点，通过定义、拆解、对比方式归纳

##  任务执行

-   **强制要求**：加载 Skill 后，**首先将以下步骤转换为 Todo 列表**，再执行后续操作
    -   完整阅读待总结文章的全部内容，梳理文章中核心概念
    -   根据核心概念总结文章主旨
    -   综合考虑待总结文章、知识库笔记中概念
    -   梳理、建立文章概念之间关系网
    -   比对知识库内 `README.md` 文件，检查知识库内是否有 `.md` 笔记文件覆盖文章主旨
        -   若存在文件覆盖文章主旨，直接更新现有 `.md` 笔记文件
        -   否则，在合适目录下创建 `.md` 笔记文件
    -   针对待总结文章中每个核心概念
        -   若核心概念未出现过，则开始 *构建概念*
        -   否则，辨析、对比并在必要时 *更新概念*
    -   笔记初稿完成后，请对笔记内容是否 **包含文章全部要点、并更新*
    -   笔记内容检查完毕后，检查笔记是否 **符合 Markdown 文本的格式要求、并修正**
    -   最后，检查并更新 `README.md` 文档

##  知识笔记构建

-   知识笔记构建（以下即为 *知识笔记构序* 这个概念的构建）
    -   识别核心概念：**通读文档（或目录下全部文档）内容**，确认核心概念
    -   构建或更新概念：综合文档内容，将概念精确定义、描述，或者是阐述概念的核心思想、机制
    -   建立关系：梳理、建立各概念之间关系

### 识别（核心）概念

-   识别核心概念：通读文章，确认文章主题、核心概念
    -   文章重点讨论的内容才是核心概念
    -   核心概念不仅可能是名词、短语，也可能是行为动作
        -   比如，“*Attention Mechanism* 注意力机制” 就是典型的名词概念
        -   而，“识别核心概念” 就是典型行为动作概念

### 构建概念

-   构建概念：综合文章内容，将概念精确定义、描述，或者是阐述概念的核心思想、机制
    -   概念定义：精确、唯一的一句话介绍
        -   概念定义不是简单的名词解释，可以是有区分的核心用途、目的等等
        -   概念定义应使用 `：` 分隔概念名称、定义内容
        -   概念若同时存在中文、英文名称，应同时给出，并使用 `* ... *` 斜体标记、并空格分隔
    -   概念描述：应包含概念 **各角度** 要点，比如：应用场合、优缺点、步骤、区别点等
        -   概念各角度应该分点叙述，不要用大段的描述
        -   概念各角度也 **可视为** 独立的概念
        -   要点间存在因果、转折等逻辑关系时，应使用 `则，`、`故，`、`即，`、`也即，` 等直观地引导
    -   注意：文章的叙述顺序不等于知识的逻辑顺序
        -   需要将分散的知识点按真正的逻辑顺序总结、归纳
        -   将文章中知识点提取、重构、梳理并归纳总结为概念

### 建立关系

-   建立关系：梳理、建立各概念之间关系
    -   总分关系：概念之间存在包含、依赖或其他类似的 *总分关系*
        -   典型的总分关系包括
            -   总概念由多个不同的子概念组成
            -   总概念可分化为子概念
            -   总概念可拆分多个步骤子概念
        -   若子概念本身较为简单，可以直接作为母概念的要点
        -   否则，子概念可以在母概念中简要介绍，然后作为独立要点构建
    -   并列关系：概念之间在某个方面相似
        -   并列的概念独立构建
        -   可重点描述概念之间区别点
        -   逻辑上，并联的概念总应归属于一个总概念，可在总概念层面使用 **表格** 直观对比

##  章节内容规范

-   章节内容规范
    -   不要长段落，尽量拆解为无序列表
        -   每个章节内容应该就是一个无序列表
        -   且大部分情况，无序列表首项应为章节标题、及其定义
    -   若同类概念较多、拆解角度类似时，应使用表格归纳、对比
        -   表格常用于 *API* 速查、概念对比、分类归纳
    -   章节末尾添加形如的参考资料、链接
    -   使用 *LaTeX* 数学公式
    -   重要图片应保存在文档同级别 `imgs/` 目录下，并插入文档内
        -   图片文件名根据具体含义按 *snake_case* **重命名**
        -   对 `.jpg`、`.jpeg` 等位图，后缀统一修改为 `.png`
    -   流程图使用 *mermaid* 表示
